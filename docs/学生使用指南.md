1. # 需求工程 AI 技能包 — 学生使用指南

   本指南帮助你从零开始配置 Claude Code + RE Skills，并用 AI 辅助完成需求工程课程作业。

   ---

   ## 第一步：安装前置工具

   ### 1.1 安装 Claude Code

   Claude Code 是 Anthropic 官方的命令行 AI 助手。

   **macOS（推荐）：**

   ```bash
   npm install -g @anthropic-ai/claude-code
   ```

   > 需要先安装 Node.js（v18+）。如果没有安装，先运行：
   > ```bash
   > brew install node
   > ```

   **Windows：**

   ```bash
   npm install -g @anthropic-ai/claude-code
   ```

   > 需要先安装 [Node.js](https://nodejs.org/)（v18+），从官网下载安装包。

   安装完成后，在终端运行以下命令登录：

   ```bash
   claude
   ```

   首次运行会提示你登录 Anthropic 账户并绑定 API Key 或订阅。按屏幕提示完成即可。

   ### 1.2 安装 PlantUML（用于需求建模作业）

   需求建模命令会使用 PlantUML 生成用例图、状态图、E-R 图等。

   **macOS：**

   ```bash
   brew install plantuml
   ```

   **Windows：**

   1. 安装 [Java JDK](https://adoptium.net/)（PlantUML 依赖 Java）
   2. 下载 [PlantUML jar 包](https://plantuml.com/download)
   3. 将 `plantuml.jar` 放到一个固定目录，并配置环境变量

   **验证安装：**

   ```bash
   plantuml -version
   ```

   能看到版本号即表示安装成功。

   ---

   ## 第二步：安装技能到 Claude Code（全局安装）

   将 RE Skills 安装到 Claude Code 的全局技能目录，这样你在**任何目录**下启动 Claude Code 都能使用这些技能和命令。

   ### 2.1 克隆仓库

   ```bash
   git clone https://github.com/jdm4pku/RE-skills-zh.git
   ```

   ### 2.2 复制技能和命令到全局目录

   ```bash
   # 创建全局技能目录（如果不存在）
   mkdir -p ~/.claude/skills
   mkdir -p ~/.claude/commands
   
   # 复制所有技能
   cp -r RE-skills-zh/skills/* ~/.claude/skills/
   
   # 复制所有命令
   cp -r RE-skills-zh/commands/*.md ~/.claude/commands/
   ```

   安装完成后的目录结构：

   ```
   ~/.claude/
   ├── skills/                        # 全局技能目录
   │   ├── vision-and-scope/          # 愿景与范围
   │   │   ├── SKILL.md
   │   │   ├── template.md
   │   │   └── examples/sample.md
   │   ├── use-case/                  # 用例建模
   │   ├── data-modeling/             # 数据建模
   │   ├── ...                        # 其他 41 个技能
   │   └── (共 44 个技能目录)
   └── commands/                      # 全局命令目录
       ├── develop-requirements.md
       ├── model-requirements.md
       ├── write-srs.md
       └── ...                        # 其他 7 个命令
   ```

   > **说明：** `~/.claude/skills/` 下的技能是全局生效的——无论你在哪个目录启动 Claude Code，都可以使用这些技能和命令。技能对应的斜杠命令（如 `/model-requirements`）也会自动注册。

   ### 2.3 验证安装

   在任意目录启动 Claude Code，输入 `/` 查看是否能看到已安装的命令列表（如 `/develop-requirements`、`/model-requirements` 等）。

   ---

   ## 第三步：启动 Claude Code

   在你的**作业目录**下启动 Claude Code：

   ```bash
   mkdir my-project
   cd my-project
   claude
   ```

   启动后，全局安装的技能和命令已自动可用。你可以在对话中直接使用斜杠命令。

   ## 第四步：完成作业

   ### 作业一：愿景与范围文档

   愿景与范围文档（Vision and Scope Document）是需求工程的第一个交付物，描述项目的业务背景、目标、特性和范围。

   **使用命令：**

   在 Claude Code 中输入：

   ```
   为"社区老弱病残孕智慧关爱互助平台"创建完整的愿景与范围文档。
   ```

   > 将"社区老弱病残孕智慧关爱互助平台"替换为你自己的项目名称。

   **评分要点提示：**

   愿景与范围文档的评分标准（总分 100 分）重点关注：

   | 评分项 | 分值 | 关键要求 |
   |--------|------|----------|
   | 业务机遇 | 10 分 | 必须包含竞品对比表（至少 3 个现有方案），说明市场趋势和本产品优势 |
   | 愿景声明 | 10 分 | 必须使用 Moore 七关键词格式：For/Who/The/Is/That/Unlike/Our product |
   | 特性列表 | 20 分 | 每个特性需要子功能分解（2-5 个子功能）+ 特性树 |
   | 发布范围 | 16 分 | 必须包含特性×版本矩阵，说明每个版本包含哪些特性 |
   | 干系人画像 | 9 分 | 每个干系人的每个属性都必须填写具体内容，不得留空 |
   | 业务目标 | 5 分 | 必须量化（有数字、有时间框架、有衡量方法） |
   | 成功指标 | 5 分 | 基线值 → 目标值 → 衡量方法 → 时间框架 |

   **生成后检查清单：**

   - [ ] 业务机遇部分有竞品对比表格
   - [ ] 愿景声明包含 For/Who/The/Is/That/Unlike/Our product 全部七个关键词
   - [ ] 每个特性有 FE-x 编号和子功能分解
   - [ ] 有特性树（文本树形图）
   - [ ] 有特性×版本矩阵（表格形式）
   - [ ] 业务目标有量化指标（如"从 X 减少到 Y"）
   - [ ] 风险有概率和影响等级
   - [ ] 干系人画像表格每个单元格都有内容
   - [ ] 部署考虑包含基础设施、开发计划、用户培训三部分
   - [ ] 文档中没有 AI 生成痕迹（如"当然可以"、"以下是"等）

   ---

   ### 作业二：需求建模文档

   需求建模文档涵盖功能模型（用例）、行为模型（流程/状态/决策/会话）和数据模型（E-R 图）。

   **使用命令：**

   在 Claude Code 中输入：

   ```
   /model-requirements 社区老弱病残孕智慧关爱互助平台
   ```

   > 将项目名称替换为你自己的项目。如果你已经有愿景与范围文档，可以指定文件路径：
   > ```
   > /model-requirements vision-and-scope.md
   > ```

   **命令会自动完成：**

   1. **用例建模** — 识别参与者和用例，编写用例规约，生成用例图（PNG）
   2. **流程建模** — 创建泳道活动图（PNG）
   3. **状态建模** — 创建状态转换图和状态表（PNG）
   4. **决策表** — 对复杂条件逻辑创建决策表（Markdown 表格）
   5. **会话图** — 建立屏幕清单和 UI 导航路径（PNG）
   6. **数据建模** — 创建 E-R 图（PNG）
   7. **渲染与组装** — 将所有 PlantUML 图渲染为 PNG，组装为 Markdown 文档

   **输出位置：**

   ```
   requirements-modeling/
   ├── README.md                  # 主文档（包含所有模型内容和图片引用）
   └── diagrams/
       ├── use-case-diagram.png   # 用例图
       ├── activity-*.png         # 活动图
       ├── state-*.png            # 状态图
       ├── dialog-*.png           # 会话图
       └── erd.png                # E-R 图
   ```

   打开 `requirements-modeling/README.md` 即可查看完整的建模文档。

   **生成后检查清单：**

   - [ ] 每个用例有完整的用例规约（名称、编号、描述、前置条件、事件流、后置条件、约束）
   - [ ] 用例图包含所有参与者和用例的关系
   - [ ] 每个核心业务流程有泳道活动图
   - [ ] 关键领域对象有状态转换图和状态表
   - [ ] 复杂条件逻辑有决策表
   - [ ] 有屏幕清单和导航路径表
   - [ ] E-R 图包含所有实体、属性和关系（含基数标注）
   - [ ] 所有 `.puml` 文件都已渲染为 `.png` 图片
   - [ ] 文档末尾有模型交叉验证报告

   ### 更多场景示例

   #### 场景 1：需求获取 — 准备访谈或工作坊

   当你需要制定需求获取策略、准备访谈提纲或设计问卷时：

   ```
   /elicit 了解外卖骑手在恶劣天气下的配送痛点和安全需求
   ```

   Claude 会帮你选择合适的获取技术（访谈/观察/问卷/工作坊），并生成对应的准备材料。

   你也可以单独使用某个获取技能：

   ```
   我需要对 5 位医院护士进行需求访谈。请使用 elicitation-interview 技能，帮我准备一份结构化访谈提纲，主题是"护理排班系统的痛点和改进需求"。
   ```

   ---

   #### 场景 2：需求优先级排序

   当你有一组已识别的需求，需要决定先做什么时：

   ```
   /prioritize 我有以下 20 条需求，项目预算有限，第一期只能做 3 个月。请帮我选择优先级排序方法并排序。
   ```

   Claude 会先推荐合适的排序方法（MoSCoW、价值-成本-风险分析等），然后引导你完成排序，最终输出分版本的发布计划。

   ---

   #### 场景 3：处理需求变更

   当项目已进入开发阶段，收到一个变更请求时：

   ```
   /analyze-change 用户提出要在校园二手交易平台增加"拍卖"功能，允许卖家设定起拍价和截止时间，买家竞价。
   ```

   该命令会产出：变更分类、影响分析（波及哪些已有需求和模块）、工作量估算、CCB 决策建议。

   ---

   #### 场景 4：需求验证与评审

   当你完成了 SRS 或需求模型，需要在基线化之前进行评审时：

   ```
   /validate 请对当前目录下的 SRS.md 进行需求验证，检查完整性、一致性、可测试性，并生成缺陷日志。
   ```

   该命令会产出：验证计划、缺陷清单（每条缺陷标注类型和严重级别）、验证报告。

   ---

   #### 场景 5：敏捷需求工程

   当你的项目采用 Scrum/敏捷方法时：

   ```
   /agile-re 在线教育直播平台
   ```

   该命令会产出：轻量级愿景与范围、用户故事形式的产品 Backlog、Sprint-ready 的需求（含验收标准）。

   ---

   #### 场景 6：使用单个技能完成特定任务

   你不一定要用斜杠命令——也可以直接引用某个技能完成具体的小任务：

   ```
   请使用 quality-attribute 技能，为校园外卖系统定义性能、安全性和可用性方面的质量属性需求。
   请使用 stakeholder-analysis 技能，分析"智慧图书馆管理系统"的干系人，生成干系人登记表。
   请使用 context-diagram 技能，为"校园一卡通系统"绘制系统上下文图，识别外部实体和数据流。
   ```

   ## 常用提示技巧

   ### 如果生成内容不够详细

   ```
   请参考 vision-and-scope 技能中的 ChemTrack 示例，
   以同等详细程度重新生成业务机遇部分。
   ```

   ### 如果需要修改某个部分

   ```
   重新生成第 2.1 节特性列表，每个特性增加更多子功能分解，并更新特性树。
   ```

   ### 如果想查看评分标准对应的示例

   ```
   读取 vision-and-scope 技能的示例文件，
   告诉我 ChemTrack 示例中哪些部分对应了评分标准的高分项。
   ```

   ### 如果需要从愿景文档衔接到建模

   ```
   基于刚才生成的愿景与范围文档，运行 /model-requirements 生成需求建模文档。
   ```

   ## 常见问题

   ### Q: Claude Code 说找不到技能文件？

   确保技能已正确复制到全局目录：

   ```bash
   ls ~/.claude/skills/
   ls ~/.claude/commands/
   ```

   如果目录为空，重新执行第二步的复制命令。

   ### Q: PlantUML 渲染失败？

   检查 Java 是否安装：

   ```bash
   java -version
   ```

   如果没有安装 Java：

   ```bash
   # macOS
   brew install openjdk
   # 或
   brew install --cask temurin
   ```

   ### Q: 生成的文档太长或太短？

   在提示中明确要求：

   ```
   请生成一份完整的愿景与范围文档，长度参考 vision-and-scope 技能示例中的 ChemTrack 文档。
   ```

   ### Q: 如何导出为 Word 文档？

   生成的 Markdown 文件可以用 Pandoc 转换为 Word：

   ```bash
   # 安装 pandoc
   brew install pandoc    # macOS
   # 转换
   pandoc requirements-modeling/README.md -o 需求建模文档.docx
   ```
