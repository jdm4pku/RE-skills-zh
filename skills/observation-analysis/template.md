# 观察会议模板

使用此模板来规划和记录需求观察会议。

## 模板

```markdown
# 观察会议：[流程名称]

**观察者：** [姓名，角色]
**参与者：** [姓名，角色，经验水平]
**日期：** [YYYY-MM-DD]
**地点：** [物理位置]
**持续时间：** [计划时长]
**模式：** [主动（情境调查）/ 被动（工作跟随）]
**目标：** [你正在观察什么流程或工作流，以及为什么？]

---

## 会前准备
- [ ] 已定义观察范围和目标
- [ ] 已选择不同经验水平的参与者
- [ ] 已安排在真实工作时段进行（非演示展示）
- [ ] 已获得参与者及其管理者的许可

## 观察日志

| 时间 | 步骤 | 操作 | 使用的制品 | 备注/信号 |
|------|------|--------|--------------|----------------|
| | 1 | [用户做了什么] | [文档、屏幕、工具] | [变通做法/痛点/延迟/错误] |
| | 2 | | | |
| | 3 | | | |

## POET 摘要

**People（人员）：** [谁参与了？角色、交接？]
**Objects（对象）：** [使用了哪些制品？物理的和数字的？]
**Environment（环境）：** [工作空间特征、约束？]
**Tasks（任务）：** [任务顺序是什么？关键步骤花了多长时间？]

## 发现

### 识别出的变通做法
1. [变通做法描述] --> [隐含的缺口]

### 识别出的痛点
1. [沮丧或低效的描述] --> [隐含的需求]

## 提取的候选需求

| 需求 ID | 需求陈述 | 观察来源 | 优先级 |
|--------|----------------------|--------------------|----------|
| | | 步骤 [N] -- [描述] | |

## 后续行动
- [ ] 在 [日期] 前与参与者分享摘要以进行验证
- [ ] 安排与 [不同用户] 的后续观察
- [ ] 使用 writing-requirements 技能完善候选需求
```

## 说明
- 在会议过程中实时填写观察日志。
- POET 框架确保你捕获所有四个维度，而不仅仅是任务。
- 在将发现转化为需求之前，始终与参与者进行验证。
