# 判定表模板

使用此模板为复杂业务逻辑创建判定表。

## 模板

```markdown
# 判定表：[规则名称]

**日期：** [YYYY-MM-DD]
**来源：** [业务规则 ID 或利益相关者]

---

## 条件和动作

| | 规则 1 | 规则 2 | 规则 3 | 规则 4 | ... |
|---|--------|--------|--------|--------|-----|
| **条件** | | | | | |
| [条件 A？] | Y | Y | N | N | |
| [条件 B？] | Y | N | Y | N | |
| **动作** | | | | | |
| [动作 X] | X | | X | | |
| [动作 Y] | | X | | X | |

## 完整性检查
- 条件数量：[N]
- 预期规则数：2^N = [值]
- 实际规则数：[值]
- 合并的规则（含"无关"条件）：[列出]
- 缺失的规则：[无 / 列出]
- 矛盾：[无 / 列出]

## 派生需求
- 规则 1：当 [条件 A] 且 [条件 B] 时，系统应 [动作 X]。
- 规则 2：当 [条件 A] 且非 [条件 B] 时，系统应 [动作 Y]。
```

## 注意事项
- 对于 N 个二元条件，需要 2^N 条规则才能保证完整性。
- 使用"--"标记不影响结果的条件（允许合并）。
- 每条规则必须至少有一个动作。
- 不应有两条规则具有相同条件但不同动作。
