## 目的
将复杂业务逻辑表达为判定表或判定树。当多个相互作用的条件决定系统行为，而散文式需求可能产生歧义或不完整时，使用此技能。

判定表保证完整性。如果有 N 个二元条件，表就有 2^N 列。每一列都有定义的动作。没有遗漏，没有歧义。

## 关键概念

### 判定表结构

| | 规则 1 | 规则 2 | 规则 3 | 规则 4 |
|---|--------|--------|--------|--------|
| **条件** | | | | |
| 条件 A？ | Y | Y | N | N |
| 条件 B？ | Y | N | Y | N |
| **动作** | | | | |
| 动作 X | X | | X | |
| 动作 Y | | X | | X |

- **条件**（上半部分）：可以为真或假的输入条件
- **动作**（下半部分）：由条件组合触发的系统行为
- **规则**（列）：每种唯一的条件组合及其对应的动作
- **X** 标记每条规则执行哪些动作

### 判定表类型

**有限条目（Limited-entry）：** 条件为二元值（Y/N）。完全覆盖 = 2^N 条规则。

**扩展条目（Extended-entry）：** 条件具有多个值（例如，"订单总额：<$50 / $50-$100 / >$100"）。更紧凑但更难验证完整性。

### 判定树（替代表示方式）
判定树以分支图的形式展示相同的逻辑：
```
订单总额？
├── < $50
│   └── 运费：标准（$5）
├── $50 - $100
│   ├── 会员？ 
│   │   ├── 是 -> 运费：免费
│   │   └── 否 -> 运费：优惠（$3）
└── > $100
    └── 运费：免费
```

**何时使用哪种形式：**
- **判定表** -- 当完整性检查至关重要时（受监管的、安全关键的场景）。表格使遗漏清晰可见。
- **判定树** -- 当逻辑是层次化的，且某些条件仅在特定分支中才有意义时。对利益相关者而言，树更易于阅读。

### 完整性检查
对于有 N 个条件的有限条目判定表：
- 预期规则数 = 2^N
- 如果规则数较少，要么：
  - 某些组合被合并了（用"--"标记，表示"无关"）
  - 某些组合缺失了（这是一个缺陷）

### 反模式
- **遗漏列** -- 未考虑所有条件组合。这正是判定表所能防止的缺陷。
- **模糊条件** -- 使用"大订单"而非"订单总额 > $100"。条件必须精确且二元化。
- **冗余规则** -- 两列具有相同条件但不同动作。这是一种矛盾。

## 应用

### 步骤 1：识别决策

寻找包含以下语言的需求：
- "如果 X 且 Y，则……"
- "取决于……"
- "当 A 但非 B 时……"
- 多层嵌套的 if-then-else 语句

### 步骤 2：列出所有条件

提取影响结果的每个条件。对于有限条目表，将每个条件表述为是/否问题。

示例条件：
- 订单总额是否 >= $100？
- 客户是否为会员？
- 收货地址是否为国内？

### 步骤 3：列出所有可能的动作

列出每种可能的系统动作：
- 适用免费运输
- 适用标准运费
- 适用国际附加费
- 发送会员折扣优惠

### 步骤 4：构建表格

1. 计算规则数：N 个二元条件对应 2^N 条规则（3 个条件 = 2^3 = 8 条规则）
2. 系统地填写条件组合（交替 Y/N 以确保完整性）
3. 对每条规则，标记适用的动作

### 步骤 5：简化（可选）

查找对某些规则无关紧要的条件。如果无论条件 C 的值如何动作都相同，则将两条规则合并为一条，条件 C 标记为"--"。

### 步骤 6：验证

- [ ] 规则数 = 2^N（或因有文档记录的合并而更少）
- [ ] 每条规则至少有一个动作
- [ ] 没有两条规则具有相同的条件组合（无重复）
- [ ] 没有两条规则具有相同条件但不同动作（无矛盾）
- [ ] 与领域专家评审："对于这种组合，这是正确的动作吗？"

## 常见陷阱

### 陷阱 1：不完整的表格
**症状：** 3 个二元条件的表格只有 6 条规则（应为 8 条）。

**后果：** 两种组合没有定义行为。当它们在生产环境中出现时，系统会产生不可预测的行为。

**修复：** 始终计算 2^N 并处理每种组合。如果两条规则相同，使用"--"标记无关条件进行显式合并。

---

### 陷阱 2：矛盾的规则
**症状：** 两条规则具有相同的条件值但指定了不同的动作。

**后果：** 需求存在矛盾。开发人员会选择其中一个；可能选错。

**修复：** 与领域专家一起评审矛盾之处。其中一条规则是错误的——找出是哪一条。

---

### 陷阱 3：条件非二元化
**症状：** 在有限条目表中出现"客户类型：金牌 / 银牌 / 铜牌"。

**后果：** 表格不完整，因为多值条件不符合 Y/N 格式。

**修复：** 使用扩展条目表，或转化为二元条件："客户是否为金牌？"、"客户是否为银牌？"（并约束只能有一个为真）。
