# 优先级排序顾问示例

## 示例：ChemTrack 优先级排序

```markdown
## 背景
ChemTrack 项目为第1版发布确定了35个功能需求。
三个关键干系人：EHS 官员、实验室主任、实验室技术员
产品代言人。开发团队提供了部分成本数据。
目标：在4个月的时间线内确定第一版发布的范围。

## 选择答案

**问题1：** 中型集合（35个需求）
**问题2：** 小型团体（3个干系人）
**问题3：** 部分数据（相对成本估算，大致价值判断）
**问题4：** 确定发布范围（确定第1版发布的入选/淘汰）

## 推荐方法：入选/淘汰 + MoSCoW

### 第1步：第1版发布的入选/淘汰（30分钟）
与全部3个干系人进行快速二元筛选：
- 第1版发布入选：28个需求
- 淘汰（推迟到第2版及以后）：7个需求
  - FE-4（条码扫描）-- 硬件采购尚未就绪
  - FE-6（仪表板）-- 价值较低，推迟
  - CT.CATALOG.ADD.3（批量CSV导入）-- 无业务目标追溯
  - 4个报告增强功能 -- 第2年之前不需要

### 第2步：在"入选"集合内进行 MoSCoW 分类（90分钟）

| 类别 | 数量 | 需求 |
|----------|-------|-------------|
| **必须有（Must Have）** | 15（54%） | 核心化学品目录（CRUD）、CAS 验证、30天过期提醒、EPA 合规报告生成、SSO 认证、审计日志记录 |
| **应该有（Should Have）** | 8（29%） | 7天紧急提醒、高级搜索（多条件）、使用日志、过期化学品阻止 |
| **可以有（Could Have）** | 5（18%） | 可配置提醒时间、导出到 CSV、重复检测、打印标签、部门汇总报告 |
| **不会有（Won't Have，本版本）** | 0 | （已在入选/淘汰步骤中过滤） |

### 约束检查
必须有 = 占"入选"需求总数的54%（15/28）
可用容量估算：4个月内约可完成20个需求的工作量
必须有占54% = 容量充裕，有空间容纳所有应该有的需求

### 结果
开发优先级顺序：
1. 所有必须有的需求（Sprint 1-3）
2. 按价值排序的应该有需求（Sprint 3-4）
3. 如果容量允许，纳入可以有的需求（Sprint 4）

### 干系人确认
三个干系人全部签字确认。解决了一个分歧：
- EHS 官员希望将"可配置提醒时间"列为必须有
- 解决方案：默认30天提醒时间为必须有；可配置性
  为可以有（可配置增加了复杂性，固定30天满足
  监管要求）
```

**为什么这种方法有效：**
- 两轮筛选方法（入选/淘汰 + MoSCoW）适用于中型需求集
- 必须有约束（54% < 60%）确保练习产生了真正的决策
- 干系人分歧有文档记录并附有解决方案
- 结果可直接映射到 Sprint 计划
