# 状态建模模板

使用此模板创建状态转换图和状态表。

## 模板

```markdown
# 状态模型：[对象名称]

**日期：** [YYYY-MM-DD]
**作者：** [姓名]

---

## 状态

| 状态 | 描述 | 进入条件 | 是否终止状态？ |
|------|------|---------|--------------|
| [名称] | [此状态的含义] | [对象如何进入此状态] | 是/否 |

## 事件

| 事件 | 描述 | 来源 |
|------|------|------|
| [名称] | [触发此事件的条件] | 用户 / 系统 / 外部 |

## 状态表

| 状态 \ 事件 | [事件 1] | [事件 2] | [事件 3] | [事件 4] |
|------------|---------|---------|---------|---------|
| [状态 1] | [转换/动作] | | | |
| [状态 2] | | [转换/动作] | | |
| [状态 3] | | | [转换/动作] | |

单元格格式：-> [新状态] / [动作] | 错误：[消息] | --（不可能/无变化）

## 状态转换图（文本）

```
[初始] --> (状态 1) --事件 [守卫条件] / 动作--> (状态 2)
                                                  |
                                             事件 / 动作
                                                  v
                                               (状态 3) --> [终止]
```

## 导出的需求

| 需求 ID | 状态 | 事件 | 需求 |
|---------|------|------|------|
| [ID] | [状态] | [事件] | 当 [事件] 发生且对象处于 [状态] 时，系统应 [动作] |

## 守卫条件

| 守卫条件 | 定义 | 应用的状态 |
|---------|------|-----------|
| [名称] | [精确条件] | [哪些转换使用此守卫条件] |
```

## 注意事项
- 填满状态表中的每一个单元格。空单元格意味着遗漏的需求。
- 终止状态不应有出向转换。
- 每个状态（终止状态除外）必须至少有一个出向转换。
