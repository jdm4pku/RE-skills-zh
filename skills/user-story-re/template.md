# 用户故事模板（需求工程场景）

使用此模板编写包含验收标准和需求属性的用户故事。

## 模板

```markdown
### [故事 ID]: [简要标题]

**作为** [用户类别或角色]，
**我希望** [动作或能力]，
**以便** [业务价值或成果]。

#### 验收标准：
- [ ] [可测试条件 1]
- [ ] [可测试条件 2]
- [ ] [可测试条件 3]

#### 需求属性：
- **优先级：** [高/中/低]
- **来源：** [谁提出或需要此功能]
- **业务规则：** [BR-ID]
- **追溯到：** [业务目标或特性 ID]
- **状态：** [已提议/已批准/已实现/已验证]
- **Sprint：** [目标 Sprint（如已分配）]

#### INVEST 检查：
- [ ] Independent（独立性） -- 可以独立于其他故事交付
- [ ] Negotiable（可协商性） -- 实现方式可以讨论
- [ ] Valuable（有价值） -- 为用户或客户交付价值
- [ ] Estimable（可估算） -- 团队可以估算工作量
- [ ] Small（小粒度） -- 可在一个 Sprint 内完成
- [ ] Testable（可测试） -- 验收标准可以被验证
```

## 注意事项
- 使用具体的用户类别名称，而不是泛化的"用户"。
- "以便"子句必须表达真正的价值，而不是对动作的重复描述。
- 每个故事 3-7 条验收标准是目标范围。
- 如果故事未通过 INVEST 检查，在 Sprint 计划前进行修改。
