# 数据流图示例

## 示例 1：良好的数据流图（ChemTrack）

```markdown
# Level 0 DFD：ChemTrack 化学试剂库存管理系统

**项目：** ChemTrack
**版本：** 1.0
**日期：** 2025-03-20
**作者：** Sarah Chen
**上下文图来源：** ChemTrack 上下文图 v1.0

---

## 过程列表

| 过程编号 | 过程名称 | 描述 | 对应特性/用例 |
|----------|----------|------|---------------|
| 1.0 | 管理化学试剂库存 | 接收试剂信息，执行增删改查操作，维护库存数据 | FE-1 / UC-01~UC-04 |
| 2.0 | 监控过期与提醒 | 定期扫描试剂过期日期，生成并发送提醒通知 | FE-2 / UC-05~UC-06 |
| 3.0 | 生成合规报告 | 汇总库存数据，按 EPA 和州级格式生成法规合规报告 | FE-3 / UC-07~UC-08 |
| 4.0 | 管理用户与权限 | 处理用户注册、登录和角色权限分配 | UC-09~UC-10 |

## 数据存储列表

| 存储编号 | 存储名称 | 描述 | 关联 ER 实体 |
|----------|----------|------|-------------|
| D1 | 化学试剂库 | 所有化学试剂的记录（名称、CAS、数量、位置、过期日期、SDS） | Chemical |
| D2 | 用户表 | 系统用户信息（姓名、角色、权限、所属实验室） | User |
| D3 | 报告归档 | 已生成的合规报告历史记录 | Report |

## 外部实体列表

| 实体编号 | 实体名称 | 类型 |
|----------|----------|------|
| E1 | 实验室管理员 | 用户 |
| E2 | EHS 办公室 | 用户 |
| E3 | EPA 报告系统 | 外部系统 |
| E4 | 邮件服务器 | 外部系统 |

## Level 0 数据流表

| 数据流名称 | 源 | 目标 | 数据内容 |
|-----------|------|------|----------|
| 试剂信息 | E1 | P1.0 | 名称、CAS 编号、数量、存放位置、过期日期 |
| 库存查询结果 | P1.0 | E1 | 试剂列表（名称、数量、位置、状态） |
| 登录凭证 | E1 | P4.0 | 用户名、密码 |
| 认证结果 | P4.0 | E1 | 登录成功/失败、角色权限 |
| 过期提醒 | P2.0 | E4 | 收件人、即将过期的试剂列表、过期天数 |
| 提醒邮件 | E4 | E1 | 过期提醒邮件内容 |
| 报告请求 | E2 | P3.0 | 报告类型、时间范围 |
| 合规报告 | P3.0 | E2 | PDF 格式合规报告 |
| EPA 格式报告 | P3.0 | E3 | EPA 标准格式数据包 |
| 试剂记录 | P1.0 | D1 | 写入/更新的试剂数据 |
| 试剂数据 | D1 | P1.0 | 读取的试剂记录 |
| 过期日期 | D1 | P2.0 | 试剂编号、过期日期 |
| 过期状态更新 | P2.0 | D1 | 试剂编号、新状态（已过期/即将过期） |
| 库存数据 | D1 | P3.0 | 全量库存数据（用于报告生成） |
| 报告记录 | P3.0 | D3 | 已生成报告的元数据和文件 |
| 用户信息 | P4.0 | D2 | 写入/更新的用户数据 |
| 用户权限 | D2 | P4.0 | 读取的用户角色和权限 |

## 平衡验证检查表

| 上下文图数据流 | 方向 | Level 0 中的对应 | 是否平衡 |
|---------------|------|-----------------|----------|
| 试剂信息 | 输入 | E1 → P1.0 | ✓ |
| 库存查询结果 | 输出 | P1.0 → E1 | ✓ |
| 登录凭证 | 输入 | E1 → P4.0 | ✓ |
| 认证结果 | 输出 | P4.0 → E1 | ✓ |
| 过期提醒 | 输出 | P2.0 → E4 → E1 | ✓ |
| 报告请求 | 输入 | E2 → P3.0 | ✓ |
| 合规报告 | 输出 | P3.0 → E2 | ✓ |
| EPA 格式报告 | 输出 | P3.0 → E3 | ✓ |

**结论：** 上下文图中的 8 条数据流全部在 Level 0 中有对应，平衡验证通过。

---

## Level 1 DFD：1.0 管理化学试剂库存

**分解过程：** 1.0 管理化学试剂库存
**分解原因：** 该过程包含搜索、新增、编辑、SDS 管理、批量导入 5 个子功能

### 子过程列表

| 子过程编号 | 子过程名称 | 描述 |
|-----------|-----------|------|
| 1.1 | 搜索化学试剂 | 按名称/CAS/位置/过期日期检索试剂记录 |
| 1.2 | 新增化学试剂 | 录入新试剂信息并保存到数据库 |
| 1.3 | 编辑试剂记录 | 修改已有试剂的数量、位置等信息 |
| 1.4 | 管理 SDS 文档 | 上传、查看、下载安全数据表 |
| 1.5 | 批量导入试剂 | 从 CSV/Excel 文件批量导入试剂数据 |

### Level 1 数据流表

| 数据流名称 | 源 | 目标 | 数据内容 |
|-----------|------|------|----------|
| 搜索条件 | E1 | P1.1 | 关键词、CAS、位置、日期范围 |
| 搜索结果 | P1.1 | E1 | 匹配的试剂列表 |
| 试剂数据 | D1 | P1.1 | 全量试剂记录（供检索） |
| 新试剂信息 | E1 | P1.2 | 名称、CAS、数量、位置、过期日期 |
| 新增记录 | P1.2 | D1 | 新试剂的完整记录 |
| 修改请求 | E1 | P1.3 | 试剂编号、修改字段、新值 |
| 现有记录 | D1 | P1.3 | 待修改的试剂记录 |
| 更新记录 | P1.3 | D1 | 修改后的试剂记录 |
| SDS 文件 | E1 | P1.4 | PDF 格式的安全数据表 |
| SDS 文档 | P1.4 | E1 | 查看/下载的 SDS 文件 |
| SDS 存储 | P1.4 | D4 | SDS 文件和元数据 |
| SDS 读取 | D4 | P1.4 | 已存储的 SDS 文件 |
| CSV/Excel 文件 | E1 | P1.5 | 批量导入的试剂数据文件 |
| 批量写入 | P1.5 | D1 | 解析后的试剂记录（批量） |
| 导入结果 | P1.5 | E1 | 成功/失败数量、错误明细 |

### Level 1 平衡验证

| Level 0 中过程 1.0 的数据流 | 方向 | Level 1 中的对应 | 是否平衡 |
|----------------------------|------|-----------------|----------|
| 试剂信息（E1 → P1.0） | 输入 | E1 → P1.2（新增）、E1 → P1.3（编辑）、E1 → P1.5（批量） | ✓ |
| 库存查询结果（P1.0 → E1） | 输出 | P1.1 → E1（搜索结果） | ✓ |
| 试剂记录（P1.0 → D1） | 写入 | P1.2 → D1、P1.3 → D1、P1.5 → D1 | ✓ |
| 试剂数据（D1 → P1.0） | 读取 | D1 → P1.1、D1 → P1.3 | ✓ |

**结论：** Level 0 中过程 1.0 的所有输入输出在 Level 1 中均有对应，平衡验证通过。
```

**为什么这个示例有效：**
- 过程数量为 4 个，符合 3-7 的范围
- 每个过程用动宾短语命名，职责清晰
- 数据存储与 ER 实体对应，便于交叉验证
- 数据流用具体的数据内容命名（"试剂信息"而非"数据"）
- 平衡验证表逐条对照上下文图，验证结果明确
- Level 1 分解选择了最复杂的过程，子过程对应特性子功能

## 示例 2：薄弱的数据流图（反模式）

```markdown
## DFD

用户 → 系统 → 数据库

过程：
1. 处理请求
2. 管理数据
3. 生成输出
```

**为什么这个示例失败：**
- 只有 3 个模糊的过程，命名太抽象（"处理请求"可以是任何事情）
- 没有数据流标签——不知道传递的是什么数据
- 没有数据存储编号和命名
- 没有平衡验证
- 没有与上下文图的对照
- 没有 Level 1 分解
- "系统 → 数据库"不是 DFD 的正确表达——数据库应该是数据存储，不是外部实体
