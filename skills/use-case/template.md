# 用例模板

使用此模板编写单个用例规约。

## 模板

```markdown
## 用例 [ID]：[名称 -- 动词短语]

**主要参与者：** [角色或用户类别]
**优先级：** [高 / 中 / 低]
**频率：** [发生频率]
**状态：** [草稿 / 已审查 / 已批准]

### 描述
[一句话描述此用例的目标。]

### 触发条件
[什么事件导致此用例开始。]

### 前置条件
- [此用例开始前必须为真的条件]
- [这些是假设成立的，不由用例测试]

### 后置条件
- [成功完成后保证为真的条件]

### 正常流程
1. [参与者动作或系统响应]
2. [参与者动作或系统响应]
3. [参与者动作或系统响应]
4. [继续直到目标达成]

### 备选流程

**[步骤]a：[简要描述]**
在步骤 [N]，如果 [条件]：
1. [步骤]
2. [步骤]
3. [从步骤 X 继续 / 用例结束]

### 异常

**[步骤]a：[简要描述]**
在步骤 [N]，如果 [错误条件]：
1. [系统响应]
2. [参与者动作或恢复]
3. [从步骤 X 继续 / 用例结束]

### 业务规则
- [BR-ID]：[管理此用例中行为的规则]

### 备注
- [额外的上下文、约束或待解决问题]
```

## 备注
- 正常流程保持在 7-12 个步骤。如果更长，考虑拆分。
- 每个步骤应有明确的参与者（用户做 X，系统做 Y）。
- 备选流程是有效变体；异常是错误条件。
- 前置条件假设为真——它们不由此用例验证。
