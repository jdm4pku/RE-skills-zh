# 用例示例

## 示例 1：编写良好的用例

```markdown
## 用例 UC-3：处理处方配药

**主要参与者：** 药剂师
**优先级：** 高
**频率：** 所有药房门店每天 200-300 次
**状态：** 已批准

### 描述
药剂师为患者处方配药，包括药物相互作用检查、库存管理和标签打印。

### 触发条件
药剂师从"待配药"队列中选择一个处方。

### 前置条件
- 药剂师已使用有效凭证和有效执照登录
- 处方已由接待人员录入，状态为"待配药"
- 药房库存数据是最新的（最近 15 分钟内已同步）

### 后置条件
- 处方状态为"已配药"
- 药房库存已按配发数量递减
- 已创建配药记录，包含药剂师 ID、时间戳和批号
- 已打印标签，包含患者姓名、药物、剂量和用药说明
- 如为管制药品，DEA 日志已更新

### 正常流程
1. 药剂师从队列中选择一个处方。
2. 系统显示处方详情：患者姓名、出生日期、药物、剂量、处方医生和续配次数。
3. 药剂师根据处方验证患者身份。
4. 系统根据患者的当前用药列表检查药物相互作用。
5. 系统显示"未发现相互作用"。
6. 药剂师从可用库存中选择药物批次。
7. 系统验证处方数量的库存是否充足。
8. 药剂师确认配药。
9. 系统记录配药、递减库存并打印标签。
10. 药剂师贴上标签并将已配药的处方放入取药区。

### 备选流程

**3a：患者请求更新姓名/地址**
在步骤 3，如果患者提供了更新的信息：
1. 药剂师选择"更新患者信息"。
2. 系统显示可编辑的患者档案。
3. 药剂师更新信息并保存。
4. 从步骤 3 继续，显示更新后的信息。

**6a：有多个批次可用**
在步骤 6，如果该药物存在多个批次：
1. 系统显示所有可用批次及其有效期。
2. 药剂师选择最早到期的批次（先到期先出，FEFO）。
3. 从步骤 7 继续。

### 异常

**4a：检测到药物相互作用**
在步骤 4，如果系统检测到潜在的药物相互作用：
1. 系统显示相互作用警告及严重级别（严重/重大/轻微）。
2. 对于严重级别：系统阻止配药并要求处方医生授权。
3. 药剂师联系处方医生并记录授权代码。
4. 药剂师输入覆盖操作及授权代码。
5. 从步骤 6 继续。

**7a：库存不足**
在步骤 7，如果库存不足以满足全部数量：
1. 系统显示可用数量与处方数量的对比。
2. 药剂师选择"部分配药"并输入要配发的数量。
3. 系统为剩余数量创建缺货订单。
4. 从步骤 8 继续，使用部分数量。

**9a：打印机故障**
在步骤 9，如果标签打印机不可用：
1. 系统显示"打印机不可用"错误。
2. 系统保存配药记录（无论如何处方已配药）。
3. 药剂师选择备用打印机或排队等待手动打印。
4. 用例结束（配药已记录，标签打印被延迟）。

### 业务规则
- BR-7：管制药品（Schedule II-V）需要 DEA 日志记录
- BR-12：超过 12 个月的处方在没有处方医生重新授权的情况下不能配药
- BR-15：最大续配次数因药物分类而异（非管制药品：12 个月，
  Schedule III-V：6 个月，最多 5 次续配）

### 备注
- 此用例假设处方在接待环节已经过验证（参见 UC-1：录入处方）。
- 药物相互作用检查使用医院的 DrugInteract API（实时）。
```

**为什么这个用例写得好：**
- 参与者和触发条件清晰
- 正常流程为 10 个步骤（可管理）
- 备选流程涵盖合理变体（非错误）
- 异常涵盖系统故障和业务规则违规
- 后置条件具体且可验证
- 业务规则通过 ID 引用，而非内联

## 示例 2：较差的用例（反模式）

```markdown
## 用例：配药

**参与者：** 用户

### 步骤
1. 用户打开系统
2. 用户点击处方
3. 用户配药
4. 系统保存
```

**为什么这个用例失败：**
- 参与者过于笼统（"用户"——哪类用户？）
- 没有前置条件或后置条件
- 没有触发条件
- 步骤过于模糊（"配药"——怎么配？）
- 没有备选流程或异常
- 没有引用业务规则
- 完全没有错误处理
