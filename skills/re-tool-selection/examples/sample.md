# 需求工程工具选择示例

## 示例：ChemTrack 工具选择

```markdown
## 工具选择：ChemTrack 项目团队

**日期：** 2025-04-15
**评估人：** Sarah Chen，BA 负责人
**当前状况：** 需求通过 Google Sheets 管理，辅以 Word 文档

---

### 选择问答

**Q1：项目/团队规模？** 中型（4 人负责需求，预计约 350 条需求，
涉及 2 个团队：开发团队和 EHS 合规团队）

**Q2：当前工具成熟度？** 等级 1（Google Sheets 用于跟踪，
Google Docs 用于 SRS 各章节，手动可追溯性——用另一个电子表格
将需求链接到测试用例）

**Q3：主要痛点？**
1. 无法跟踪变更——没有谁在什么时候修改了什么需求的历史记录。
   Tom Rivera 上周修改了 3 条需求，直到开发人员询问一个冲突时
   才有人注意到。
2. 没有可追溯性——手动可追溯性电子表格已经过时（在 Sprint 2
   更新过一次，之后再也没更新过）。无法为 EHS 合规审计
   生成覆盖率报告。
3. 协作问题——两位分析师同时编辑了同一个 Google Doc 部分。
   其中一人的修改被悄悄覆盖了。

**Q4：集成需求？** 问题跟踪器（Jira——开发团队使用 Jira
进行 Sprint 管理和缺陷跟踪）

---

### 推荐

**基于选择逻辑：先迁移到使用 Jira 的等级 2，6 个月后评估
等级 3。**

**理由：**
- 中型团队处于等级 1，存在变更跟踪和可追溯性的痛点，
  建议等级 2-3 较为合适。
- 然而，团队已经在开发中使用 Jira。在 Jira 中添加一个
  需求项目（等级 2）比引入新的专用 RM 工具风险更低。
- Jira 提供：唯一 ID、变更历史、自定义属性、基本链接
  （用于可追溯性），以及与开发工作流的原生集成。
- Jira 不提供：丰富的可追溯性矩阵、基线比较或合规报告。
  应监控这些差距，如果变得关键，将推动等级 3 评估。

---

### 工具配置计划（Jira 作为等级 2）

**自定义问题类型："Requirement"（需求）**
- 字段：需求 ID（自定义）、类型（功能性/质量/约束）、
  优先级、状态、来源（干系人）、业务目标链接、
  验证方法
- 工作流：草稿 -> 评审中 -> 已批准 -> 已实现 -> 已验证

**通过 Jira 链接实现可追溯性：**
- 需求 -> "实现于" -> 开发 Story/Task
- 需求 -> "验证于" -> 测试用例（在 Jira 中或链接到 Zephyr）
- 需求 -> "来源于" -> 业务目标（Epic）

**变更历史：** Jira 原生审计日志记录所有字段变更，
包含时间戳和用户信息。

**接受的局限性（6 个月后重新评估）：**
- 没有正式的基线快照（变通方案：在每个基线点导出到电子表格）
- 没有基线比较功能（变通方案：手动对比导出的基线）
- 没有合规矩阵生成功能（变通方案：JQL 查询 + 手动格式化）

---

### 7 步评估（简化版——等级 2 选择）

| 步骤 | 结果 |
|------|--------|
| 1. 工具需求 | 必须：变更历史、唯一 ID、Jira 集成、多用户。最好有：可追溯性报告、基线。 |
| 2. 候选名单 | Jira（已有）、Azure DevOps（备选）、Notion（备选） |
| 3. 必备项筛选 | 三者均通过。Jira 在集成方面胜出（已在使用）。 |
| 4. 实际试用 | 50 条需求导入到 Jira 需求项目中。团队使用了 1 周。反馈："可以用。光是变更历史就值了。" |
| 5. 集成测试 | Jira 到 Jira 的链接原生支持。通过 Zephyr 插件确认测试用例链接可行。 |
| 6. 总拥有成本 | 增量许可证费用 $0（已在为 Jira 付费）。配置工作量：2 人天。培训：1 人天。 |
| 7. 决定 | ChemTrack 采用 Jira 等级 2。Sprint 5 试点。MVP 发布后重新评估是否需要等级 3 工具。 |

---

### 采纳计划

| 周次 | 活动 |
|------|----------|
| 第 1 周 | 配置 Jira 需求项目，导入 180 条需求 |
| 第 2 周 | 培训团队（2 小时实操课程） |
| 第 3 周 | 试点：Sprint 5 的需求在 Jira 中编写 |
| 第 4 周+ | 全面采纳。不再接受 Google Sheets。 |

**等级 3 重新评估触发条件：** 需求超过 500 条、合规审计要求
正式的可追溯性、或第二个产品需要变体管理。
```

**为什么有效：**
- 选择问答直接对应具体推荐并附有理由
- 推荐务实：先等级 2，不急于跳到等级 3
- 已知局限性被记录和接受，而非忽视
- 触发条件定义了何时重新评估，防止过早或延迟升级
- 采纳计划包含培训和旧工具的硬性截止日期
- 总拥有成本分析表明增量成本接近零，使决策变得简单
