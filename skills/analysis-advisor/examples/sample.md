# 分析顾问示例

## 示例：ChemTrack 分析技术选择

```markdown
## 分析技术选择：ChemTrack 化学品库存系统

**日期：** 2025-03-27
**分析师：** Sarah Chen
**项目：** ChemTrack —— 大学化学品库存与合规系统

---

### 选择回答

**Q1：主要需求类型重点？**
回答：**均衡型** —— ChemTrack 涉及用户交互（实验室技术人员
管理化学品）、数据管理（具有复杂属性的化学品记录）、业务逻辑
（处置授权规则、GHS 分类）以及事件驱动行为（化学品过期
生命周期、警报触发）。

**Q2：系统复杂度？**
回答：**中-高** —— 4 种用户类型（实验室技术人员、实验室主管、
EHS 专员、部门管理员），计划约 40 个功能，法规要求（EPA、OSHA），
与大学 SSO 和采购系统的集成。

**Q3：团队建模经验？**
回答：**基础** —— Sarah 使用过流程图和简单 ERD。James
（开发负责人）熟悉 UML 类图。Lisa（测试负责人）没有使用过
正式的建模技术。没有团队成员之前创建过状态转换表或正式的
决策表。

**Q4：最大的担忧？**
回答：**未处理的状态** —— 化学品生命周期很复杂（活跃、即将过期、
已过期、已处置、已转移），EHS 专员强调每个状态转换都必须
被准确记录以维持法规合规。化学品"卡"在未处理的状态中就是
合规违规。

---

### 推荐

**始终应用的基线：**
1. **上下文图（Context Diagram）** —— 定义系统边界，识别 6 个外部
   实体，推导接口需求。工作量：1-2 小时。
2. **数据字典（Data Dictionary）** —— 定义所有数据元素（化学品名称、CAS 号、
   数量、位置、危险类别等）。工作量：2-3 小时。

**选定的技术（基于 Q1-Q4）：**

3. **User Story**（替代完整 Use Case）
   - 理由：团队经验为基础级别（Q3）。User Story 对所有团队成员
     来说都易于理解。完整 Use Case 需要团队目前没有时间进行的培训。
   - 工作量：初始集 3-4 小时

4. **化学品记录的状态模型**（主要关注点技术）
   - 理由：Q4 确定未处理的状态为最大担忧。
     状态：活跃、即将过期、已过期、已处置、已转移。
     每个状态-事件单元格必须被显式填充。
   - 工作量：2-3 小时

5. **处置授权的决策表**
   - 理由：3 个交互条件（危险品？> 阈值？已过期？）= 8 条
     规则需要枚举。复杂逻辑需要完整性验证。
   - 工作量：1-2 小时

**不推荐的技术（附理由）：**
- 完整 Use Case —— 团队经验太基础，无法使用完整格式
- BPMN 流程模型 —— 团队未使用过正式的流程符号
- 对话图（Dialog Map） —— UI 较为简单，不是主要关注点
- 完整 ERD —— 数据字典已提供足够的数据定义

---

### 预期成果

| 技术 | 预期发现 |
|------|---------|
| 上下文图 | SSO、采购系统、EPA 门户的接口需求 |
| 数据字典 | 精确定义，防止所有其他工件中的歧义 |
| User Story | 4 种用户类型的完整功能集及验收标准 |
| 状态模型 | 缺失的转换、未处理的事件、法规状态约束 |
| 决策表 | 完整的处置授权规则（3 个条件产生 8 条规则） |

**预计总分析工作量：** 1-2 周内 10-14 小时

---

### 交叉引用计划

创建所有模型后，验证一致性：
- [ ] 上下文图中的每个外部实体至少有一个
      User Story
- [ ] 状态模型中的每个状态至少出现在一个
      User Story 的验收标准中
- [ ] 数据字典中的每个数据元素至少被一个
      User Story 或状态模型引用
- [ ] 决策表中的每个条件映射到一个已定义的
      数据元素
- [ ] 决策表中的每个动作映射到一个状态转换
      或 User Story
```

**为什么有效：**
- 选择回答针对 ChemTrack 的具体场景，而非泛泛而谈
- 理由解释了为什么选择每种技术以及为什么拒绝其他技术
- 团队经验（基础级别）直接影响了选择 User Story 而非完整 Use Case 的决策
- 主要关注点（未处理的状态）驱动了将状态建模作为关键技术的选择
- 预期成果具体且可衡量，而非模糊不清
- 交叉引用计划确保模型协同工作，而非各自孤立
- 工作量估算帮助团队合理规划分析阶段
