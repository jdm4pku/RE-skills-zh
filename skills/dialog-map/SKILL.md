## 目的
创建对话图以建模用户如何在系统用户界面中进行导航。使用此技能构建完整的界面清单、定义界面间的转换规则，并发现用例和用户故事通常遗漏的 UI 需求。

这不是线框图或视觉设计——它是一个导航模型，展示存在哪些界面、每个界面上有哪些可用操作，以及每个操作将用户带到哪里。

## 关键概念

### 对话图元素

| 元素 | 符号 | 描述 |
|------|------|------|
| 对话框/界面（Dialog box / Screen） | 圆角矩形 | 用户交互的一个独立界面、页面或对话框 |
| 导航路径（Navigation path） | 箭头 | 从一个界面到另一个界面的转换 |
| 操作触发器（Action trigger） | 箭头上的标签 | 引起转换的用户操作或系统事件 |
| 决策点（Decision point） | 菱形 | 基于条件的分支（例如基于角色的路由） |
| 起始点（Start point） | 实心圆 | 系统或子系统的入口点 |
| 终止点（End point） | 靶心圆 | 退出点（登出、关闭、完成） |
| 子流程（Subprocess） | 双边框矩形 | 在单独对话图中建模的一组界面 |

### 界面清单

界面清单记录系统中每个独立界面：

| 界面 ID | 界面名称 | 用途 | 父界面 | 访问角色 |
|---------|----------|------|--------|----------|
| SCR-01 | Login（登录） | 验证用户身份 | 无（入口） | 全部 |
| SCR-02 | Dashboard（仪表盘） | 显示摘要和导航 | Login | 所有已认证用户 |
| SCR-03 | Chemical Search（化学品搜索） | 搜索和筛选化学品 | Dashboard | 技术员、EHS 专员 |

### 转换规则

对话图中的每条箭头都有一个转换规则：

```
From（来源）: [源界面]
To（目标）: [目标界面]
Trigger（触发器）: [用户操作或系统事件]
Guard（守卫条件）: [必须为真的条件]
Action（动作）: [转换过程中发生的操作]
```

### 对话图与用例的关联

每个用例步骤映射到一个或多个界面：

| 用例步骤 | 界面 | 界面上的用户操作 |
|----------|------|-----------------|
| UC-3 步骤 1：技术员选择"添加化学品" | Dashboard（SCR-02） | 点击"添加化学品"按钮 |
| UC-3 步骤 2：系统显示录入表单 | Add Chemical Form（SCR-04） | 系统导航至表单 |
| UC-3 步骤 3：技术员输入化学品数据 | Add Chemical Form（SCR-04） | 填写字段，点击"保存" |
| UC-3 步骤 4：系统验证并保存 | Confirmation（SCR-05） | 系统显示确认信息 |

### 为什么有效

对话图能揭示其他技术遗漏的导航需求：
- "用户在确认界面按返回键会发生什么？"
- "用户能否从搜索结果直接导航到编辑界面，还是必须先经过查看界面？"
- "哪些界面需要取消按钮，取消后导航到哪里？"
- "存在哪些错误界面，用户如何从错误中恢复？"

### 反模式

- **死胡同界面** -- 没有出口导航的界面（用户被困住了）
- **不可达界面** -- 没有入口导航的界面（用户如何到达那里？）
- **缺失错误路径** -- 只建模正常路径的导航；忽略验证失败和错误恢复
- **界面膨胀** -- 将每个细微变化都作为独立界面，而不是在一个界面上使用条件内容

## 应用

使用 `template.md` 作为填写结构。

### 步骤 1：从用例中盘点界面

遍历每个用例，列出用户交互的每个独立界面：
- 入口界面（登录、着陆页）
- 任务界面（表单、搜索、列表视图）
- 确认和结果界面
- 错误和帮助界面
- 设置和个人资料界面

### 步骤 2：构建界面清单表

为每个界面记录：
- 唯一的界面 ID
- 描述性名称
- 主要用途
- 哪些用例引用了该界面
- 哪些用户角色可以访问该界面

### 步骤 3：映射导航路径

为每个界面，识别用户离开它的所有方式：
- 主要操作（提交、保存、搜索）
- 次要操作（取消、返回、帮助）
- 系统触发的转换（超时、错误重定向）
- 基于角色的路由（管理员进入仪表盘 A，普通用户进入仪表盘 B）

### 步骤 4：定义转换规则

为每条导航路径指定：
- 触发器：什么用户操作或事件引起转换？
- 守卫条件：必须满足什么条件？（例如表单有效、用户有权限）
- 动作：转换过程中发生什么处理？（例如保存数据、发送通知）

### 步骤 5：绘制对话图

布局界面和箭头：
1. 将入口点放在顶部或左侧
2. 主路径从左到右或从上到下流动
3. 分支显示替代路径和错误路径
4. 在导航依赖条件的地方标记决策点
5. 确保每个界面至少有一条入口路径和一条出口路径（入口和出口除外）

### 步骤 6：验证完整性

- [ ] 每个用例步骤都映射到对话图中的一个界面
- [ ] 每个界面至少有一条入口路径（入口点除外）
- [ ] 每个界面至少有一条出口路径（终止点除外）
- [ ] 用例中的错误和异常流程都有对应的导航路径
- [ ] 为每个适用的界面定义了取消和返回导航
- [ ] 每个界面都标记了基于角色的访问控制
- [ ] 定义了帮助访问方式（全局或界面特定）
- [ ] 为处理敏感数据的界面指定了超时行为

### 步骤 7：派生 UI 需求

为每个界面派生需求：
```
系统应显示 [界面名称]，展示 [内容]。
当用户在 [界面名称] 上执行 [操作] 时，系统应导航到 [目标界面]。
如果 [界面名称] 上出现 [错误条件]，系统应显示 [错误消息] 并 [恢复路径]。
```

## 示例

参见 `examples/sample.md` 获取 ChemTrack 的完整对话图规格说明。

简要示例（文本表示）：

```
[Login] --有效凭证--> [Dashboard]
[Login] --无效凭证--> [Login]（显示错误消息）
[Dashboard] --点击"添加化学品"--> [Add Chemical Form]
[Dashboard] --点击"搜索"--> [Chemical Search]
[Add Chemical Form] --提交有效数据--> [Confirmation]
[Add Chemical Form] --取消--> [Dashboard]
[Add Chemical Form] --验证错误--> [Add Chemical Form]（显示错误）
[Confirmation] --点击"确定"--> [Dashboard]
[Chemical Search] --选择结果--> [Chemical Detail]
[Chemical Detail] --点击"编辑"--> [Edit Chemical Form]
[Chemical Detail] --点击"返回"--> [Chemical Search]
```

## 常见陷阱

### 陷阱 1：只建模正常路径
**症状：** 对话图展示了理想的导航序列，但没有展示用户犯错、取消或遇到错误时会发生什么。

**后果：** 错误恢复界面和导航在开发期间临时设计，导致用户体验不一致。

**修复：** 对每个界面，问："如果用户取消会怎样？如果验证失败会怎样？如果授权失败会怎样？如果超时会怎样？"为每种情况添加路径。

---

### 陷阱 2：没有返回导航
**症状：** 对话图展示了前进导航，但没有返回的方式。

**后果：** 用户无法返回之前的界面时会感到沮丧。开发人员不一致地添加返回按钮。

**修复：** 为每个界面明确定义返回/取消导航。指定返回是"返回上一个界面"还是"返回特定界面"。

---

### 陷阱 3：缺少界面清单
**症状：** 绘制了对话图，但没有包含 ID、用途和角色访问权限的正式界面列表。

**后果：** 界面在实现过程中被重复、命名不一致或遗忘。

**修复：** 在对话图旁边维护一个界面清单表。图中的每个界面都必须出现在清单中。

---

### 陷阱 4：将对话图与线框图混淆
**症状：** 对话图包含了详细的布局、颜色、字体和控件位置。

**后果：** 过早花时间在视觉设计上；导航需求被设计细节掩盖。

**修复：** 对话图只展示界面（带标签的方框）和转换（带标签的箭头）。视觉设计在对话图之后进行，以对话图为依据。关于原型设计，参见 `skills/prototyping-strategy/SKILL.md`。
