# 需求风险评估模板

使用此模板来记录和跟踪需求工程风险。

## 模板

```markdown
# RE 风险登记册：[项目名称]

**版本：** [x.y]
**日期：** [YYYY-MM-DD]
**评估人：** [姓名]
**评估范围：** [获取 / 分析 / 规格说明 / 确认 / 管理 / 全部]

---

## 风险：[RR-ID]

- **风险名称：** [简短描述性名称]
- **类别：** [获取 / 分析 / 规格说明 / 确认 / 管理]
- **风险陈述：** IF [具体条件]，THEN [具体后果]。
- **概率：** [高 (3) / 中 (2) / 低 (1)] -- [简要理由]
- **影响：** [高 (3) / 中 (2) / 低 (1)] -- [简要理由]
- **暴露度：** [概率 x 影响 得分]
- **受影响的需求：** [风险发生时受影响的需求 ID]
- **缓解策略：** [规避 / 缓解 / 转移 / 接受]
- **缓解行动：** [要采取的具体行动]
- **负责人：** [负责缓解的人员]
- **截止日期：** [缓解必须完成的日期]
- **状态：** [已识别 / 缓解进行中 / 已缓解 / 已发生 / 已关闭]

*（对每个风险重复以上内容）*

---

## 风险暴露度汇总

| 风险 ID | 名称 | 类别 | 概率 | 影响 | 暴露度 | 状态 |
|---------|------|----------|------|--------|----------|--------|
| [RR-ID] | [名称] | [类别] | [1-3] | [1-3] | [1-9] | [状态] |

---

## 评审日志

| 日期 | 评审人 | 变更内容 |
|------|----------|-------------|
| [YYYY-MM-DD] | [姓名] | [本次评审周期中的变更内容] |
```

## 注意事项
- 每个风险陈述都使用条件-后果格式。"需求不好"不是风险。
- 在每个项目里程碑时重新评估概率和影响。
- 暴露度 >= 6 的风险需要指定负责人进行主动缓解。
- 当风险发生时，记录实际影响并纳入经验教训。
- 至少每个 Sprint 或每个项目阶段关卡审查一次登记册。
