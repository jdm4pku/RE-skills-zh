# 变更影响分析示例

## 示例：ChemTrack 实验室库存系统 -- CR-007 条码扫描

```markdown
# 变更影响分析

## 变更请求摘要

| 属性 | 值 |
|------|-----|
| **CR ID：** | CR-007 |
| **提交日期：** | 2025-05-10 |
| **请求者：** | Dr. James Lee（实验室主任） |
| **变更类型：** | 增强 |
| **优先级：** | 中 |
| **描述：** | 为化学品容器识别添加条码扫描功能，自动填充记录以替代手动键盘录入。 |
| **理由：** | 手动录入每个容器需要约 2 分钟。扫描可将时间缩短至约 15 秒，并减少数据录入错误。 |

## 影响清单
- [ ] 与现有需求冲突？——否
- [x] 影响质量属性？——性能（扫描延迟 < 2 秒）、可用性
- [x] 需要架构变更？——新的硬件接口层
- [x] 影响外部接口？——条码扫描仪硬件 API
- [ ] 改变业务规则？——否
- [x] 引入法规义务？——GHS 条码格式合规性
- [x] 影响用户文档或培训？——新的扫描工作流
- [ ] 使现有测试用例失效？——否
- [x] 创建新的依赖关系？——条码硬件采购（6 周交付周期）

## 受影响的工作产品

| 工作产品 | 具体项 | 变更性质 |
|---------|--------|---------|
| SRS | FR-01（化学品录入）；新增 FR-45（条码扫描） | 修改；添加 |
| SRS | NFR-03（响应时间） | 修改——添加扫描延迟目标 |
| 架构 | 组件图；接口规格说明 | 添加 ScannerInterface 模块 |
| UI 设计 | 化学品录入界面 | 添加扫描按钮和反馈区域 |
| 测试计划 | 集成和性能测试套件 | 添加扫描测试用例 |
| 用户手册 | 化学品录入流程 | 添加扫描工作流 |
| 培训 | 实验室技术员模块 | 添加扫描操作流程 |
| 部署 | 5 个实验室的硬件安装 | 添加安装流程 |

## 工作量和进度估算

| 任务 | 估算工作量 |
|------|-----------|
| 需求更新 | 4 小时 |
| 架构更新 | 8 小时 |
| UI 设计更新 | 6 小时 |
| 扫描仪 API 集成 | 24 小时 |
| GHS 条码解析器 | 8 小时 |
| 单元和集成测试 | 20 小时 |
| 性能测试 | 4 小时 |
| 文档和培训 | 8 小时 |
| 硬件安装（5 个实验室） | 8 小时 |
| **合计** | **90 小时（约 2.5 个开发者周）** |

- **进度影响：** 如果在 Release 1 中实施则 +1.5 个冲刺；如果推迟到 Release 2 则 +0
- **成本影响：** $10,800 开发费用 + $3,500 硬件费用 = 总计 $14,300

## 风险和替代方案

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|---------|
| 扫描仪与实验室环境不兼容 | 中 | 高 | 指定工业级设备；先在 1 个实验室试点 |
| GHS 条码解析错误 | 低 | 中 | 使用 GHS Rev. 9 测试数据集进行验证 |
| 采购延迟超过 6 周 | 中 | 中 | 立即启动采购流程 |

| 替代方案 | 优点 | 缺点 | 工作量 |
|---------|------|------|--------|
| 按提议的条码扫描方案 | 最快的录入方式；最少的错误 | 成本高；硬件依赖 | 90 小时 + $3,500 |
| 带化学品数据库的自动完成 | 无需硬件 | 比扫描慢 | 30 小时 |
| 什么都不做（手动录入） | 无成本 | 缓慢且易出错的录入方式持续存在 | 0 小时 |

## 建议
**建议：** 推迟到 Release 2
**理由：** 手动录入变通方案对 Release 1 来说已经够用。硬件交付
周期带来进度风险。实施自动完成功能（30 小时）作为临时解决方案。
**条件：** 立即启动硬件采购以确保 Release 2 就绪。

## CCB 决策
| 日期 | 决策 | 决策者 | 条件 |
|------|------|--------|------|
| 2025-05-15 | 推迟到 Release 2 | M. Johnson, S. Chen, T. Rivera | 已启动采购；自动完成功能作为 CR-008 获批 |
```

**为什么这个示例有效：**
- 影响清单揭示了不明显的影响（GHS 合规性、硬件驱动）
- 受影响的工作产品在所有工件类型中系统性地追溯
- 工作量包括测试、文档和硬件——不仅仅是编码
- 比较了三个替代方案，包括"什么都不做"
- 建议具有可操作性，附带条件和临时缓解措施
