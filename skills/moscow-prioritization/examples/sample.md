# MoSCoW 优先级排序示例

## 示例：ChemTrack 实验室库存管理系统 -- Release 1

```markdown
# MoSCoW 优先级排序：ChemTrack

**日期：** 2025-04-05
**作者：** Sarah Chen（业务分析师）
**时间盒：** Release 1（12 周，Sprint 1-6）
**总可用工作量：** 200 故事点

---

## 时间盒约束
- **周期：** 12 周（6 个两周迭代）
- **团队产能：** 200 故事点（2 名开发人员 + 1 名测试人员，约 33 点/迭代）
- **硬性截止日期：** 州 EPA 合规审计定于第 16 周；
  合规功能必须提前上线以留出测试缓冲
- **外部依赖：** 条码扫描硬件采购需要 6 周交付周期（尚未订购）

---

## Must Have（必须有）——目标：<= 120 点（60%）

| 需求 ID | 需求描述 | 工作量 | 试金石测试依据 |
|---------|---------|--------|--------------|
| FR-01 | 添加/编辑/删除化学品记录 | 20 点 | 核心 CRUD——没有它系统毫无用处 |
| FR-05 | 带筛选条件的化学品搜索 | 13 点 | 不能在大规模数据中定位化学品；没有变通方案 |
| FR-12 | 过期日期提醒 | 15 点 | 安全要求；过期化学品是实验室隐患 |
| FR-15 | 法规合规报告生成 | 25 点 | EPA 审计在第 16 周；合同义务 |
| FR-22 | 危险分类显示 | 8 点 | GHS 合规；实验室安全要求 |
| FR-42 | 审计追踪日志 | 13 点 | 合规报告所需；没有手动替代方案 |
| FR-38 | 用户角色管理 | 10 点 | 安全基线；没有访问控制无法上线 |
| **小计** | | **104 点** | **占 200 的 52%——低于 60% 上限** |

---

## Should Have（应该有）——目标：约 40 点（20%）

| 需求 ID | 需求描述 | 工作量 | 放弃时的变通方案 |
|---------|---------|--------|----------------|
| FR-33 | SDS 文档链接 | 12 点 | 技术人员在制造商网站上手动查找 SDS |
| FR-25 | 化学品处置跟踪 | 15 点 | 用纸质表单跟踪处置；在 Release 2 中录入系统 |
| FR-35 | 位置/存储跟踪 | 13 点 | 维护现有电子表格记录位置；后续集成 |
| **小计** | | **40 点** | **占 200 的 20%——达到目标** |

---

## Could Have（可以有）——目标：约 40 点（20%）

| 需求 ID | 需求描述 | 工作量 | 纳入的价值 |
|---------|---------|--------|-----------|
| FR-18 | 实验室主任仪表板 | 18 点 | 主任可以一目了然地查看概况；否则使用标准报告 |
| FR-28 | 从电子表格批量导入 | 15 点 | 加速初始数据迁移；否则手动录入 |
| **小计** | | **33 点** | **占 200 的 16.5%——可接受** |

---

## Won't Have（不会有）（本次发布）

| 需求 ID | 需求描述 | 排除理由 | 重新评估时间 |
|---------|---------|---------|-------------|
| FR-08 | 条码扫描 | 硬件采购需要 6 周交付周期；尚未订购。存在手动录入的变通方案。 | Release 2（Q3）——现在开始订购硬件 |
| FR-30 | 移动端友好界面 | 高工作量（30 点）但效益中等。桌面端访问对实验室环境已足够。 | Release 2——在获取用户采纳数据后评估 |
| FR-40 | 采购系统集成 | 采购 系统 API 在 Q4 之前不可用。外部依赖阻碍交付。 | Release 2 或 3——取决于采购 API 时间线 |

---

## 分配汇总

| 类别 | 工作量 | 占总量 % | 目标 % | 状态 |
|------|-------|---------|--------|------|
| Must Have | 104 点 | 52% | <= 60% | 正常——8% 缓冲 |
| Should Have | 40 点 | 20% | ~20% | 正常——达到目标 |
| Could Have | 33 点 | 16.5% | ~20% | 正常——略低 |
| Won't Have | 约 55 点 | 不适用 | 不适用 | 已排除 |
| **总承诺量** | **177 点** | **88.5%** | | **23 点应急储备** |

**应急分析：** 23 点未承诺的产能提供了范围调整的缓冲。
如果某个 Must Have 花费的时间超过预估，首先放弃 Could Have，
然后是 Should Have。104 点的 Must Have 承诺在达到 60% 上限之前
还有额外的 16 点缓冲。

---

```

**为什么这个分类有效：**
- Must Have 条目通过了试金石测试：每一项要么是核心功能，要么是法规要求
- Must Have 工作量为 52%，远低于 60% 上限，提供了应急缓冲
- Should Have 条目记录了放弃时的变通方案
- Won't Have 条目有明确的理由和重新评估时间线
- 分配汇总验证了 60/20/20 分布
- 总承诺工作量（177/200）留出了 23 点的应急缓冲
