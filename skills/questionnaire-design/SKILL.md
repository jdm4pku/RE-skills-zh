## 目的
设计需求问卷，在无法进行个别访谈时从大量利益相关者中收集结构化数据。问卷可以将需求获取扩展到大规模受众，但会牺牲深度——它们用于确认和排列已知内容的优先级，而非发现新需求。

这不是访谈（参见 `skills/elicitation-interview/SKILL.md`）或观察（参见 `skills/observation-analysis/SKILL.md`）的替代品。应在初始需求获取*之后*使用问卷，以在更广泛的人群中验证、排序和量化已有发现。

## 关键概念

### 问卷适用场景（与访谈的对比）

| 标准 | 问卷 | 访谈 |
|------|------|------|
| 受众规模 | 20+利益相关者 | 每次1-5人 |
| 问题类型 | 封闭式、结构化、预定义选项 | 开放式、探索性 |
| 发现能力 | 低——确认已知需求 | 高——发现新需求 |
| 深度 | 浅——无法追问 | 深——可以探查和澄清 |
| 地理覆盖 | 任何地点，异步进行 | 需要安排时间和物理接触 |
| 偏差风险 | 问题措辞、顺序效应 | 访谈者引导、亲和效应 |
| 最佳时机 | 初始需求获取之后 | 需求发现的早期阶段 |

**经验法则：** 先通过访谈发现需求，再通过问卷与更大群体验证和排序优先级。

### 问题类型

**开放式问题（自由文本）**
- 邀请自由形式的回答
- 大规模分析难度较大
- 少量使用（每份问卷1-3个）
- 示例："当前化学品库存流程中最大的问题是什么？"

**封闭式问题（结构化）**

| 类型 | 适用场景 | 示例 |
|------|---------|------|
| **是/否** | 二元确认 | "您目前是否跟踪化学品有效期？" |
| **多选题** | 从已知选项中选择 | "您最常使用哪种化学品搜索方式？(a) 名称 (b) CAS号 (c) 位置 (d) 有效期" |
| **Likert量表** | 衡量同意程度或满意度 | "请评价您对当前库存流程的满意度：1（非常不满意）到 5（非常满意）" |
| **排序题** | 排列偏好顺序 | "请将以下功能按重要性从1（最重要）到5（最不重要）排序" |
| **强制选择** | 权衡分析 | "如果只能选一个，您会选择：更快的搜索 还是 过期提醒？" |

### 量表设计

**Likert量表：**
- 使用5点或7点量表（5点最常见）
- 始终标注所有刻度点，而非仅端点
- 包含中立中间点（例如"既不同意也不反对"）
- 使用平衡标签（正面和负面选项间距相等）

```
1 = 非常不同意
2 = 不同意
3 = 既不同意也不反对
4 = 同意
5 = 非常同意
```

**排序题：**
- 限制在5-7个选项（更多会造成认知负担）
- 明确说明"1"的含义（最重要还是最不重要）
- 需要清晰优先级时，强制排序优于允许并列

**强制选择：**
- 恰好呈现2个选项
- 需要迫使对方做出权衡决策时使用
- 不要与Likert量表混合使用（属于不同的认知任务）

### 为什么有效
- **定量数据** 用数字而非观点来支撑优先级讨论
- **广泛覆盖** 确保最响亮的利益相关者不会主导需求
- **匿名性** 减少从众心理和社会期望偏差
- **结构化格式** 使不同受访者的结果可比较

### 反模式
- **发现式问卷** —— 试图用调查从零开始发现需求。问卷用于确认，而非探索。
- **50题怪兽** —— 超过15题后，每增加5题完成率下降20%。保持简短。
- **引导性量表** —— "您多喜欢这个功能？(1) 喜欢 (2) 非常喜欢 (3) 离不开它。"没有否定选项。
- **双重含义问题** —— "当前系统是否快速且易用？"快速和易用是两个独立的问题。

## 应用

使用 `template.md` 作为问卷结构。

### 第1步：定义问卷目标

在编写问题之前，明确：
1. **这些数据将为什么决策提供依据？**（例如"第1版本包含哪些功能"）
2. **你已经知道什么？**（来自访谈和观察）
3. **这份问卷填补什么空白？**（例如"我们知道5位用户想要提醒功能，但其他195人是否同意？"）
4. **目标受众是谁？**（用户类别、部门、经验水平）

### 第2步：起草问题

**问题排序规则：**
1. 从简单的、事实性问题开始（人口统计、角色、经验）
2. 转向观点和偏好问题
3. 将敏感或复杂问题放在中间（而非开头或结尾）
4. 以开放式问题结束（供额外评论）
5. 将相关问题分组

**偏差避免清单：**
- [ ] 没有引导性问题（"您是否同意……"）
- [ ] 没有双重含义问题（每个问题只涉及一个概念）
- [ ] 没有带有倾向性的用词（"过时的系统"与"当前系统"）
- [ ] 没有假设受访者具备某些知识（"评价API性能"而用户可能不使用API）
- [ ] 量表平衡（正面和负面选项数量相等）
- [ ] 可能的情况下随机排列多选题选项顺序

### 第3步：设计回答结构

对每个问题，指定：
- 问题类型（开放式/封闭式、量表类型）
- 必答还是选答
- 回答选项（带有清晰标签）
- 跳转逻辑（如适用："如果您在Q3选择了否，请跳至Q7"）

### 第4步：试点测试

正式部署前：
1. 将问卷发给3-5人
2. 计时完成所需时间（目标：10分钟以内）
3. 询问："有哪些问题让您困惑？"和"有没有您想回答但未被问到的问题？"
4. 根据反馈修改

### 第5步：部署和收集

**按受众规模的分发策略：**

| 受众规模 | 方法 | 目标回复率 |
|---------|------|-----------|
| < 50 | 直接发送带有个人呼吁的邮件 | 60-80% |
| 50-200 | 带有管理层背书的邮件 | 40-60% |
| 200+ | 多渠道（邮件、内网、会议） | 30-50% |

**提高回复率的技巧：**
- 总时间控制在10分钟以内
- 以个人名义发送，而非系统发送（"发件人：Alex Rivera"而非"发件人：noreply@"）
- 说明结果将如何使用
- 设定明确的截止日期（7-10个工作日）
- 在中间时间点发送一次提醒

### 第6步：分析结果

1. 计算回复率并检查无回复偏差（某些群体是否回复不足？）
2. 对Likert量表：报告均值、中位数和分布（3.5的均值可能掩盖双峰分裂）
3. 对排序题：计算加权分数和排名顺序
4. 对开放式问题：将回答编码为主题
5. 按用户类别交叉列表，发现群体间差异
6. 报告发现并关联到需求决策

简要示例摘录：

```markdown
**Q5：请按重要性排序以下ChemTrack功能（1 = 最重要）：**
- [ ] 过期日期提醒
- [ ] 按CAS号搜索
- [ ] 自动合规报告
- [ ] 实验室移动端数据录入
- [ ] 重复化学品检测

**结果（n=87名受访者）：**
| 功能 | 加权分数 | 排名 |
|------|---------|------|
| 过期提醒 | 4.3 | 1 |
| 按CAS号搜索 | 3.8 | 2 |
| 移动端数据录入 | 3.2 | 3 |
| 重复检测 | 2.5 | 4 |
| 合规报告 | 1.2 | 5 |
```

## 常见陷阱

### 陷阱1：将问卷用于需求发现
**症状：** 首次与利益相关者接触就是一份包含"您需要什么？"等开放式问题的调查。

**后果：** 回答质量低、内容模糊。你还不够了解情况，无法提出好问题。

**修正：** 先访谈和观察。使用问卷来验证和排序已经了解到的内容。

---

### 陷阱2：双重含义问题
**症状：** "当前系统是否快速且易用？"将两个概念合并在一起。

**后果：** 如果受访者认为系统快但难用，就无法准确回答。数据无法解读。

**修正：** 每个问题只涉及一个概念。拆分为"当前系统是否快速？"和"当前系统是否易用？"

---

### 陷阱3：忽视无回复偏差
**症状：** 30%的回复率，但将结果作为代表性数据报告。

**后果：** 未回复的70%可能有不同需求。通常满意的用户不会费心回复，导致结果偏向负面。

**修正：** 追踪谁回复了、谁没回复。跟进未回复者。在每个发现旁都报告回复率。

---

### 陷阱4：问题过多
**症状：** 问卷有40+个问题。完成率仅15%。

**后果：** 只有最有动力（或最不满）的利益相关者会完成。结果存在偏差。

**修正：** 限制在15-20个问题。每个问题必须通过："这个回答将为什么决策提供依据？"删除未通过的问题。

---

### 陷阱5：不平衡的量表
**症状：** 量表选项为：优秀、良好、一般、差。三个正面选项和一个负面选项。

**后果：** 回答偏向正面。无法区分"满意"和"非常满意"。

**修正：** 使用平衡量表：非常满意、满意、中立、不满意、非常不满意。
