# 变更控制流程示例：ChemTrack Release 1

## 背景
ChemTrack Release 1 的需求在 Sprint 0 之后完成基线化。团队已建立变更控制委员会（CCB）并定义了变更控制流程。开发进行两个月后，变更请求开始陆续到来。

---

## CCB 章程摘要

**CCB 成员：**
- Dr. Sarah Chen（实验室主任 / 产品负责人）— 主席
- Mark Torres（BA / Scrum Master）— 秘书
- Dr. James Lee（EHS 官员）— 领域专家
- Priya Patel（首席开发人员）— 技术顾问
- Prof. Rodriguez（实验室技术员代表）— 用户代表

**决策规则：** 多数投票。主席裁决平票。技术否决权归首席开发人员（针对可行性问题）。
**会议频率：** 两周一次，紧急请求可临时召开。

## 变更请求 CR-003：添加条形码扫描

### 步骤 1：提交

| 属性 | 值 |
|------|-----|
| CR ID | CR-003 |
| 标题 | 为化学品登记添加条形码扫描功能 |
| 发起人 | Prof. Rodriguez |
| 提交日期 | 2026-03-15 |
| 来源 | Sprint 2 评审期间的用户反馈 |
| 描述 | 实验室技术员希望扫描化学品容器上的条形码，而不是手动输入 CAS 编号。可减少错误并节省时间。 |
| 业务理由 | 技术员反映每种化学品的手动录入需要 3-5 分钟；扫描可将时间缩短至 30 秒。每月登记 200+ 种化学品。 |
| 优先级（发起人评估） | 应该有（Should Have） |

### 步骤 2：分类

**变更类型：** 增强（新能力，非缺陷修复）
**范围：** 影响登记工作流（US-101、US-102），需要硬件（USB 条形码扫描仪），新的外部接口。
**是否适用快速通道？** 否 — 影响多个需求，需要硬件采购，涉及外部接口。

### 步骤 3：影响分析

**使用 `skills/change-impact-analysis/SKILL.md`：**

**影响检查清单：**
- [x] 影响现有功能需求（US-101：登记化学品）
- [x] 需要新的外部接口（条形码扫描仪硬件）
- [x] 影响 UI 设计（登记表单需要扫描按钮/字段）
- [ ] 影响安全需求 — 否
- [x] 影响测试范围（需要新的设备集成测试）
- [ ] 影响数据模型 — 否（CAS 编号字段已存在）
- [x] 影响部署（扫描仪驱动安装、硬件采购）

**受影响的工作产品：**

| 工作产品 | 影响 |
|----------|------|
| SRS 第 3.1 节（化学品登记） | 添加条形码扫描仪作为输入方式 |
| SRS 第 2.1 节（外部接口） | 添加条形码扫描仪接口规格 |
| 上下文图 | 添加"条形码扫描仪"作为外部实体 |
| UI 原型 | 修改登记表单以包含扫描按钮 |
| 测试计划 | 添加扫描仪集成测试（8 个测试用例） |
| 用户手册 | 添加扫描操作说明 |

**工作量估算：**

| 任务 | 工时 |
|------|------|
| 需求更新（SRS、上下文图） | 4 |
| UI 设计（扫描按钮、反馈） | 8 |
| 后端（条形码解析、CAS 查询） | 16 |
| 扫描仪集成（驱动、USB 接口） | 12 |
| 测试（单元测试 + 集成测试 + UAT） | 16 |
| 文档（用户手册） | 4 |
| 硬件采购和安装 | 8 |
| **合计** | **68 工时** |

**进度影响：** 如果立即开始，增加 +1.5 个迭代（3 周）。可与 Sprint 4 的工作并行进行。

**风险评估：**
- 硬件依赖：扫描仪采购（2 周交付周期）
- 跨操作系统的扫描仪兼容性（Linux 实验室工作站）
- 新工作流的用户培训

### 步骤 4：CCB 决策

**会议日期：** 2026-03-22
**出席者：** 全部 5 名 CCB 成员

**讨论摘要：**
- Prof. Rodriguez 强烈支持："这每月可为所有实验室节省 40+ 小时"
- Priya Patel："技术上可行，但需要 3 周。Linux 上的扫描仪驱动是个风险。"
- Dr. Lee："非合规关键项。手动输入 CAS 编号对审计来说也可以。"
- Dr. Chen："确实有价值，但不在 Release 1 范围内。我们已承诺 EPA 审计截止日期。"

**决策：** **延期至 Release 2**

**理由：** 该功能价值明确（每月节省 40+ 小时），但为 Release 1 增加 3 周会危及 EPA 审计截止日期。条形码扫描是 Release 2 待办列表的首要优先项。

**条件：**
- 立即开始硬件采购（2 周交付周期不会延迟 Release 2）
- 在 Release 2 规划中将条形码扫描添加为 EP-R2-001
- 将决策和时间表通知 Prof. Rodriguez

### 步骤 5：决策后跟踪

|------|-----|

| 计划版本 | Release 2 |
| 延期日期 | 2026-03-22 |
| 采购已启动 | 2026-03-23 |
| 发起人已通知 | 2026-03-22 |

## 变更请求 CR-005：修复合规报告日期范围

### 步骤 1：提交

| 属性 | 值 |
|------|-----|
| CR ID | CR-005 |
| 标题 | 合规报告未按日期范围过滤 |
| 发起人 | Dr. James Lee（EHS 官员） |
| 提交日期 | 2026-04-01 |
| 来源 | 合规报告 UAT 期间发现 |
| 描述 | 合规报告生成所有时间的数据。EPA 审计要求月度报告。系统必须支持按日期范围过滤。 |
| 业务理由 | EPA 审计要求月度化学品处置报告。当前报告无法用于审计。 |
| 优先级（发起人评估） | 必须有（Must Have） |

### 步骤 2：分类

**变更类型：** 缺陷（遗漏的需求 — REQ-103 指定了"月度报告"但未指定日期范围过滤）
**是否适用快速通道？** 是 — 单一需求，低风险，高紧迫性（EPA 审计在 6 周后）

### 步骤 3：影响分析（快速通道）

**工作量：** 12 工时（4 小时需求、4 小时开发、4 小时测试）
**风险：** 低 — 对报告查询的隔离性变更
**受影响需求：** REQ-103（合规报告）

### 步骤 4：CCB 决策

**决策方式：** 邮件审批（快速通道流程）
**决策：** **已批准**（24 小时内全票通过）
**理由：** 在验证过程中发现的需求缺陷。EPA 审计合规是必须有的业务目标。低工作量，低风险。
